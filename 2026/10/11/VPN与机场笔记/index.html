VPN & 机场笔记（资料备份）

⚠️ 说明：本文为资料备份与信息收集性质，整理自公开资料与他人笔记（原始出处：mikeah2011 · VPN & 机场笔记）。机场信息时效性极强，跑路风险高，永远不要年付——月付或「不限时小包」最安全。

本文不含任何推广导流链接（原文的邀请码已移除），仅保留判断标准与选购方法论。

永远先看这条

  • 不要年付。 月付或不限时小包最安全，机场跑路时损失最小。
  • 不要只买一家。 组合推荐：一个月付 + 一个不限时套餐 = 最稳方案。
  • 优先选择运营 1 年以上、有工单/Telegram 群、支持 24 小时退款的机场。

一、主流代理协议对比

选择协议是科学上网的第一步。以下是目前最主流的四种协议在加密方式、抗封锁能力、性能、跨平台支持四个维度的对比：

维度 Shadowsocks (SS) V2Ray (VMess/VLESS) Trojan WireGuard
加密方式 AEAD (ChaCha20-Poly1305 / AES-256-GCM) VMess: AES-128-GCM；VLESS: 无内置加密（依赖 TLS） TLS 1.3（伪装为 HTTPS 流量） ChaCha20-Poly1305 / Curve25519
流量特征 特征明显，易被 DPI 识别 VMess 有特征；VLESS+XTLS 几乎无特征 与正常 HTTPS 网站流量一致 有独特握手特征，需搭配隧道
抗封锁能力 ⭐⭐⭐ 中等（需配合 obfs 插件） ⭐⭐⭐⭐ 较强（VLESS+Reality 极强） ⭐⭐⭐⭐⭐ 极强 ⭐⭐⭐ 中等（裸连易被识别）
性能 高 中（VMess 稍高开销） 中高 极高（内核态实现）
跨平台 全平台 全平台 全平台 全平台
适用场景 自建、轻度使用 自建 / 机场主流 对抗 DPI 组网、内网穿透

协议趋势

  • VLESS + Reality 正在取代 VMess，成为新标准（无自签证书、抗探测强）
  • AnyTLS 协议开始出现，部分机场陆续支持
  • AI 用途（ChatGPT / Claude）推动了高端专线需求——对 IP 质量要求高

方案二：Surge（进阶）

Surge 是 macOS/iOS 上功能最强大的网络调试与代理工具，价格较高（$49.99 起），但功能远超 Clash：

  • 原生支持 HTTP 抓包和请求重写
  • 支持增强模式（Enhanced Mode）代理所有应用
  • 低内存占用，稳定性极佳
  • 支持 iCloud 同步配置

方案三：Proxifier（仅代理特定应用）

如果你只想让特定应用走代理（如只让浏览器翻墙、其他直连），Proxifier 是最佳选择，支持按进程名、按 IP 段设置不同规则。

四、机场选购方法论

4.1 直连 vs 中转 vs 专线

类型 原理 速度 稳定性 价格 适合人群
直连 客户端直接连接境外节点 受国际带宽影响 一般 低 预算有限、轻度使用
中转 经过国内中转服务器再出境 较快（中转优化路由） 较好 中 日常使用、追求体验
专线 (IEPL/IPLC) 企业级专线通道 极快且稳定 极好 高 重度用户、开发者、对稳定性要求高

4.2 机场评分维度

选择机场时，建议从以下维度综合评估：

  1. 节点覆盖：支持多少个国家/地区？是否有常用节点（日本、新加坡、美国、香港）
  2. 协议支持：是否支持 Trojan / VLESS 等新协议？（老旧 SS 可能被封）
  3. 流媒体解锁：是否支持 Netflix、Disney+、ChatGPT 等？
  4. 倍率说明：部分节点倍率 > 1，实际消耗流量更多，需注意
  5. 在线客服：是否有工单系统或 Telegram 群组？
  6. 退款政策：是否支持不满意退款？（至少支持 24 小时内退款）
  7. 历史口碑：查看是否有跑路风险，选择运营 1 年以上的老机场

4.3 按预算的选购思路

这里不列具体机场清单（时效性太差），只给判断标准：

使用强度 推荐类型 预算参考 选购要点
低频（月 < 100GB） 直连月付 ¥2 起 只要便宜、能失联自救
囤流量 不限时流量包 ¥20 / 1TB 级 看倍率是否 1:1，注意「阅后即焚」
追求体验 中转月付 ¥10 / 100GB 级 看是否有 BGP 中转、晚高峰是否稳
重度 / AI 用途 专线（IEPL/IPLC） ¥40 起 IP 质量是关键，看是否原生 IP

4.4 避坑清单

  • ❌ 年付：跑路事件频发，损失最大的就是年付用户
  • ❌ 只看价格：¥1 月付往往意味着超售，晚高峰根本跑不动
  • ❌ 只买一家：单点故障时你会完全没有备用方案
  • ❌ 忽略倍率：倍率标注混乱，实际消耗可能远超套餐名义流量
  • ✅ 先试用：优先选提供 1-2GB 试用流量或 1 天试用的机场

五、故障排查踩坑记录

案例 1：Clash Verge Rev 与 Surge 同时运行冲突

同时运行两个客户端会导致代理端口冲突（默认都是 7890），表现为浏览器无法上网。解决方法：修改其中一个客户端的端口号，或只保留一个运行。

案例 2：公司 / 学校网络封锁代理

部分公司/学校网络会通过 DPI 深度包检测封锁代理流量。表现：机场节点全部超时，但手机 4G 正常。解决方法：选择 Trojan 协议节点，或使用 VLESS + Reality 节点（伪装为正常 HTTPS 流量）。

案例 3：路由器代理后局域网设备无法直连

在路由器层面配置代理后，局域网内的 AirDrop、打印机、智能家居设备可能无法被发现。解决方法：在路由器的代理规则中添加局域网 IP 段 192.168.0.0/16、10.0.0.0/8 为直连规则。

案例 4：Git 推送失败但浏览器正常

浏览器走了系统代理，但 Git 默认不读系统代理。解决方法：给 Git 单独配置代理（见上文 macOS 代理配置），或在代理客户端里开启 TUN 模式，让所有流量（含终端）都被接管。

案例 5：订阅更新后节点全红

多为订阅链接失效或机场更换域名。解决方法：到机场官网（而非邮件里的旧链接）重新复制订阅地址；若官网也打不开，说明机场可能已跑路。

七、备份与归档建议

作为一份「资料备份」，建议按下面的方式维护：

  1. 订阅链接存本地：存进密码管理器（如 Bitwarden），不要只存在浏览器书签里
  2. 每季度复核一次：机场域名、价格、状态都可能变化，过期信息及时标注或删除
  3. 保留方法论，弱化清单：具体的机场名随时会失效，判断标准（协议、类型、避坑项）才是长期有价值的部分
  4. 记录自己的踩坑：把每次翻车的原因写下来，比记十个机场名有用

Hexo 博客优化完整路线

发表于2026-10-06|更新于2026-11-16|Hexo 教程
|总字数:1.7k|阅读时长:5分钟|浏览量:

优化顺序不该从“再加一个插件”开始。对于同时包含文章、相册、文献和本地工作台的网站，先保证内容正确、首屏能读、交互稳定，再用测量结果决定是否增加构建复杂度。

本文只描述本站已采用的做法和下一步判断方法。 不用其他网站的评分、通用压缩比例或托管平台宣传，代替本机与真实设备上的验证。

一、按影响排序

顺序 先解决什么 验收方式
1 文章与实际功能、指令一致 对照源码和页面，照步骤能完成任务
2 首屏和手机阅读 iPhone 15 尺寸检查菜单、标题、表格与遮挡
3 脚本与第三方资源可靠性 连续换页，检查重复事件、网络失败和降级
4 图片、代码与长内容体积 对比相同页面与资源的加载结果
5 构建和发布可追溯 预览与正式使用同一候选包

二、先选对预览环境

用 npm run dev 查看静态热更新。检查标题层级、段落、代码块和图片，不在这个环境判断云端接口是否可用。

用 npm run preview。它先构建并运行本地 Pages Functions；KV/D1 与线上分开，接口凭据需本地配置。真实云端内容的验收应在已配置的预览环境进行。

用 npm run dev:desktop。文献解析、标注和模拟引擎需在本机运行，网页上的一个按钮不能替代后台服务的启动与恢复检查。

当前统一 Node 版本为 22。完整启动和发布流程见 工程化实战。

三、内容排版：先减重复，再加外挂

文章前两屏应该回答什么

  1. 这篇文章适用于什么版本或场景？
  2. 读完能完成什么任务？
  3. 最短操作路径是什么，哪些前提不能漏？

把这三件事放在前面，完整日志、旧方案和长推导放到后面。文章摘要与开头不必再重复同一段背景。

内容关系 合适的呈现
必须记住的前提、易错概念 少量 Note 提示块
可以任选其一的方案 两到三个 Tabs
连续操作步骤 正常编号列表，保持展开
完整配置、附加推导、历史背景 折叠区
数据、参数或机制对照 表格，保留单位与来源

写法与实际效果见 标签外挂手册。避免把重要限制藏起来，也不要给每一段加背景色。

四、图片与资源加载

图片先匹配显示用途

相册缩略图和大图承担不同任务：列表优先较小预览，查看时再加载大图。本站相册通过 ImageKit 接口读取文件夹内容，图片是否成功显示要同时检查缩略图和灯箱。

文章中的示意图优先使用清晰、有文字说明的图；已有 SVG 不必为了“动起来”换成更重的组件。新增图片应有替代文字，图中数据应能找到对应来源。

第三方库保留来源与校验

本站关键库采用本地文件，清单记录在 tools/vendor-manifest.json。这改善了对特定第三方资源链路的依赖，但不代表所有网络资源都已离线化。

新增压缩插件之前，先做一次可比测量

记录改动前后的同一个页面、同一设备或视口、相同缓存条件：

  • 传输量与主要资源大小；
  • 首屏图片出现和正文可读的时间；
  • 菜单、Tabs、灯箱和 Pjax 换页是否仍正常；
  • 构建是否明显变慢。

只有收益明确、回归可控时再引入压缩或打包工具。没有测量数据，就不在文章中写“体积减少一半”或固定的性能提升。

五、手机布局与长页面

手机检查统一采用 393 × 852 CSS 像素的 iPhone 15 尺寸，再检查桌面 1440 × 900。需要确认：

  • 页面整体不出现横向滚动；表格和代码只在自己的区域滚动。
  • Tabs 按钮能换行或在自身区域滚动，不挤出屏幕。
  • 浮动导航、助手和底部工具不盖住正文与最后一个操作。
  • 折叠区用清楚的标题说明里面是什么，展开后能自然继续阅读。
  • 从列表进入文章、切换页面再返回，操作仍可用。

这组视口只是基础验证，不能代替所有手机和辅助技术测试。

六、缓存与发布各管一件事

内容 当前位置或入口 需要注意
Hexo 索引与产物 db.json、public/ 构建缓存不等于数据备份
本地接口状态 .tmp/workflow/local-state/ 清理会影响本地测试记录
发布候选包 .tmp/workflow/releases/ 验收后不改包内文件
图片与外链缓存 各功能自己的缓存策略 不能用一种“清缓存”解决所有问题

npm run build 准备主题和研思共享文件，再干净生成网页；日报与历史数据显式用 data:refresh 更新。CI 缓存依赖、执行检查，不承担本站当前的自动生产发布。

正式发布前先验收候选包。 旧的跳过构建、直接上传 public/ 或一键推送所有远程的路径，已不再作为日常发布入口。

七、托管平台怎样选

本站已有 Cloudflare Pages Functions、D1/KV 和口令接口，因此当前以 Cloudflare 作为正式网站运行环境。GitHub Pages 可以托管静态页面，但不执行这些 Functions。

不要为了“多线部署”在没有验证域名、证书、接口和数据一致性的情况下把同一站点拆到多个平台。HTTPS、访问控制与性能也应分别处理，不能用关闭 HTTPS 代替排查。

平台配额、计费和区域可用性会变化，选型时再查对应服务的官方说明；本文不保留未经复核的免费额度与速度排名。

八、下一轮优化怎么决定

先收集一个具体问题：哪个页面、什么视口、哪一步慢或看不清。再选最小改动验证，记录收益和副作用；确认有效后再推广到同类页面。

功能索引见 博客魔改总览，实际启动指令见 站点说明书。

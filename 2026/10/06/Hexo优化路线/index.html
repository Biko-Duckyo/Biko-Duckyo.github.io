Hexo 博客优化完整路线

优化路线总览

博客搭建

最推荐的本地开发环境。

  1. 安装 Node.js LTS
  2. 安装 Git
  3. npm install hexo-cli -g
  4. hexo init 初始化

适合服务器部署和命令行熟悉者。
建议先配置好 zsh + vim 开发环境。

用 Termux 终端模拟器，功能有限。
适合临时写文章，不适合长期开发。

GitHub Actions 自动部署

把本地的 hexo g -d 放到线上自动跑。

好处：

  • 本地只写文章，git push 就自动部署
  • 源码版本管理，出错随时回滚
  • 增量提交，速度快

需要在 GitHub 仓库新建 .github/workflows/deploy.yml。

托管平台对比

  • 优点：免费 CDN，部署简单
  • 缺点：国内访问慢
  • 适合：面向海外读者
  • 优点：功能丰富，支持表单
  • 缺点：国内访问慢
  • 适合：需要额外功能
  • 优点：全球 CDN，免费
  • 缺点：workers.dev 域名被墙，需绑自定义域名
  • 适合：有自己域名的用户
  • 优点：国内访问快
  • 缺点：需实名认证，容量有限
  • 适合：纯国内读者

多线部署

通过 DNS 按线路分流：

  • 境外访问 → GitHub Pages
  • 电信用户 → Vercel
  • 移动用户 → Netlify

注意：不同平台 SSL 证书不通用，不要强制 HTTPS。

静态资源优化

优化项 效果 难度
图片压缩 减小 50%+ 体积 简单
CDN 加速 静态资源加载快 简单
异步加载 首屏快 中等
Gulp 压缩 自动压缩 较难

注意：jsdelivr 国内速度已变差，慎用。

PWA / pjax / Gulp

这三个并称”bug 御三家”：

  • PWA：功能非刚需，bug 多，难卸载
  • pjax：页面无刷新，但容易出兼容问题
  • Gulp：配置繁琐，提升有限

非刚需别硬上。

全站 CDN

国内 CDN 必须备案，这是硬性要求。

备案流程：

  1. 国内注册域名（阿里云/腾讯云）
  2. 域名服务商提交备案
  3. 客服初审材料
  4. 管局审核（3天~1个月）

没有备案号用不了国内 CDN。
